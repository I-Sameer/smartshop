1. Executive Summary & Problem Context
The Vision: ShopSmart is a hyper-scale global marketplace connecting millions of customers to an extensive catalog spanning electronics, fashion, home appliances, books, healthcare, and groceries. While high catalog volume drives growth, it simultaneously introduces friction across customer engagement and merchant fulfillment.
Core Dilemma: Modern shoppers encounter decision paralysis when navigating multi-tiered catalogs, ambiguity around delivery timelines and return windows, and slow customer support channels. Simultaneously, operational and logistics teams struggle with cross-warehouse stock visibility, dynamic replenishment forecasting, and consistent fulfillment coordination.
ShopSmart AI resolves both ends of this equation by unifying Generative AI, Retrieval-Augmented Generation (RAG), and Agentic Workflows into a single cohesive e-commerce engine. The platform transforms passive search into proactive advisory and manual logistics into automated operational intelligence.
📌 Strategic Value PropositionBy integrating an Express.js backend with PostgreSQL + pgvector and LangChain multi-agent workflows, ShopSmart delivers sub-100ms structured intent understanding, 100% grounded policy retrieval with verbatim audit citations, and autonomous warehouse routing.

Architectural Decision Record (ADR): Why Node.js & pgvector?
Unified Multi-Model Storage: Deploying a separate standalone vector database (such as Pinecone, Qdrant, or Weaviate) introduces dual-write synchronization bugs, eventual consistency drift, and redundant network latency. With PostgreSQL 16 and the pgvector extension, product metadata, inventory levels, user orders, and vector embeddings reside in the exact same transactional engine. An inventory decrease or product update occurs within a single atomic ACID transaction alongside its vector embedding update.
Node.js Event-Driven Performance: Node.js and Express offer native JSON interoperability, non-blocking I/O, and first-class LangChain.js support. The streaming capabilities of Express facilitate real-time token delivery to the React frontend while maintaining a lean microservice footprint.
3. End-to-End System Architecture Blueprint
The ShopSmart AI platform follows a clean four-tier architectural pattern separating presentation, gateway and security, application intelligence, and persistent multi-model data storage.
Figure: ShopSmart AI End-to-End System Architecture (Archify Style Blueprint)
Detailed Architectural Tier Breakdown
Tier 1: Client Experience Layer — Constructed with React 19 and Vite. Houses both the traditional e-commerce browsing journey (category trees, faceted filtering, comparisons, cart, checkout) and the interactive AI Conversational Copilot. Communicates strictly over TLS 1.3 via RESTful JSON APIs.
Tier 2: API Gateway & Application Services — Powered by Node.js and Express. Implements defense-in-depth through Helmet HTTP security headers, CORS origin whitelisting, rate limiting per IP, and JWT token authentication with RBAC. Dispatches validated payloads to domain-specific services.
Tier 3: AI Agents & RAG Subsystem — The cognitive heart of ShopSmart. Orchestrated via LangChain.js, incoming customer queries are routed to specialized sub-agents (Shopping Intent, Knowledge RAG, Logistics, Operations). Each agent executes isolated tools with strict output constraints.
Tier 4: Relational & Vector Storage Layer — PostgreSQL 16 acts as both the relational system of record and the high-speed semantic search index. GIN indexes power full-text lexical queries, while HNSW vector indexes calculate Cosine Distance (<=>) for 1536-dimensional embeddings in under 12 milliseconds.

ShopSmart AI addresses the hackathon's two core functional mandates through two specialized, decoupled pipelines:

Module 1: AI-Powered Product Discovery Flow
Workflow Analysis: When a user enters a complex prompt like 'Suggest a laptop under $1000 for Java development and AI projects', the Shopping Agent initiates a multi-stage evaluation:
1. Semantic Intent Extraction: Identifies product category (Laptop), budget ceiling ($1000), and targeted use cases (Java Development, AI/Machine Learning).
2. Specification Filtering: Derives mandatory hardware baselines (RAM >= 16GB, multi-core CPU, dedicated SSD storage).
3. Hybrid Multi-Factor Ranking: Evaluates matching items based on price-to-budget ratio, customer rating, review volume, and in-stock inventory status.
4. Explainable Response Generation: Produces a structured JSON payload containing exact product codes, real-time prices, and human-readable justifications.

Module 2: RAG Enterprise Knowledge Assistant
Zero-Hallucination Policy: To guarantee that answers to critical policy inquiries (returns, shipping guarantees, warranties) are 100% truthful and grounded in corporate policy, the RAG agent employs an enterprise ingestion and retrieval pipeline:
1. Multi-Format Ingestion: Ingests PDF, Markdown, and JSON documents with document category, effective date, and version metadata.
2. Semantic Text Chunking: Applies a recursive character splitter with 1000-character windows and 200-character overlaps to maintain sentence integrity across boundaries.
3. Vector Retrieval: Queries are vectorized and matched against stored chunks in pgvector using Cosine Similarity.
4. Grounded Prompting & Hallucination Guard: The LLM is instructed under strict system rules to answer exclusively from the provided context. If context is insufficient, it responds with a graceful fallback.

Database Indexing Strategy
To guarantee high query throughput even under heavy concurrent load, the schema establishes specialized indexing structures:
• GIN Full-Text Index: Created on `products.search_vector` driven by an automated PostgreSQL trigger for instant lexical matching across name, brand, and description.
• HNSW Vector Indexes: Configured with `m=16, ef_construction=64` on `document_chunks.embedding` and `products.embedding` for logarithmic approximate nearest neighbor retrieval.
• B-Tree Composite Indexes: Established on `(user_id, status)` on orders and `(category_id, price, rating)` on products to ensure instantaneous faceted filtering.

8. Security Architecture & AI Audit Governance
Defense-in-Depth: Because ShopSmart AI handles user credentials, financial transactions, and AI-driven advice, security and explainability are enforced through nine structural defense layers:
1. Cryptographic Authentication: Stateless JWT tokens with 24-hour expiration and bcrypt password hashing with 12 salt rounds.
2. Role-Based Access Control (RBAC): Strict middleware guards enforcing customer vs administrative boundaries.
3. Rate Limiting: IP-based sliding window rate limiters (100 req/min general, 10 req/min for AI endpoints, 20 per 15 min for auth).
4. SQL Injection Protection: Parameterized queries across all database drivers.
5. AI Prompt Injection Defense: System prompt isolation, input sanitization, and structured JSON output schema enforcement.
6. Comprehensive AI Audit Logging: Every recommendation and RAG response is recorded in the `ai_interactions` table capturing the raw query, user ID, model response, confidence score, and latency.
📌 Auditable & Explainable AI MandateEvery AI-driven output in ShopSmart AI is fully explainable. Recommendations provide human-readable 'reason' strings tied directly to verified hardware specs, and RAG answers provide document title, section heading, version number, and relevance confidence.

Quickstart Deployment Instructions
1. Start PostgreSQL with pgvector: docker run -p 5432:5432 -e POSTGRES_PASSWORD=postgres pgvector/pgvector:pg16
2. Run Database Migrations: cd server && npm run migrate
3. Seed Mock Enterprise Data: cd server && npm run seed
4. Start Express Backend: cd server && npm run dev (Running on port 5000)
5. Start React 19 Frontend: cd client && npm run dev (Running on port 5173)
